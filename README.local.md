# راهنمای تست محلی UI — قبل از دیپلوی

این راهنما پنل واقعی را با دیتابیس **محلی و جداگانه** اجرا می‌کند؛ چیزی روی Cloudflare دیپلوی نمی‌شود. برای دیدن ظاهر و فرم‌ها به اکانت Cloudflare یا database_id واقعی نیاز ندارید.

## ۱. پیش‌نیاز و نصب

Node.js نسخهٔ ۲۲ به‌روز یا ۲۴ و npm نصب باشد. در ترمینال PowerShell داخل VS Code:

```powershell
Set-Location 'D:\AI-Project\claude\xray-panel-cf-worker'
node --version
npm --version
npm ci
```

اگر پروژه را جابه‌جا کرده‌اید، مسیر دستور اول را تغییر دهید. نصب اولیهٔ وابستگی‌ها اینترنت می‌خواهد. اگر PowerShell اجرای `npm.ps1` را مسدود کرد، از `npm.cmd` و `npx.cmd` به‌جای `npm` و `npx` استفاده کنید؛ نیازی به تغییر سیاست امنیتی سیستم نیست.

## ۲. ساخت دیتابیس آزمایشی

```powershell
npx wrangler d1 migrations apply persianpl-panel --local --persist-to .wrangler/ui-preview
```

اگر تأیید خواست، `y` بزنید. این دستور باید migration را با موفقیت اجرا کند. تکرارش اشکالی ندارد؛ migrationهای اجراشده دوباره اعمال نمی‌شوند.

داده‌ها در `D:\AI-Project\claude\xray-panel-cf-worker\.wrangler\ui-preview` می‌مانند و از دیتابیس پیش‌فرض توسعه جدا هستند. **در تمام دستورهای این راهنما همین `--persist-to` را نگه دارید.** مقدار فعلی `REPLACE_WITH_YOUR_D1_ID` برای این اجرای محلی مانع نبود؛ برای تست UI آن را تغییر ندهید.

## ۳. اجرای پنل

```powershell
npx wrangler dev --local --ip 127.0.0.1 --port 8788 --persist-to .wrangler/ui-preview --var ADMIN_USER:admin --var ADMIN_PASS:ui-preview-2026 --var PANEL_PATH:uipreview
```

ترمینال را باز نگه دارید و بعد از پیام `Ready` در مرورگر باز کنید:

**http://localhost:8788/uipreview**

| ورودی | مقدار آزمایشی |
|---|---|
| نام کاربری | `admin` |
| رمز عبور | `ui-preview-2026` |
| کد دومرحله‌ای | در دیتابیس تازه فعال نیست؛ خالی بگذارید |

این رمز عمومی و **فقط برای تست روی دستگاه خودتان** است. سرور را با tunnel یا آدرس `0.0.0.0` عمومی نکنید و این رمز را در محیط واقعی به کار نبرید. متغیر درست رمز در این پروژه `ADMIN_PASS` است، نه `ADMIN_PASSWORD`.

**نکتهٔ مهم:** متغیرهای بالا فقط هنگام ساخت اولیهٔ تنظیمات استفاده می‌شوند. اگر قبلاً همین دیتابیس را با مسیر یا رمز دیگری راه انداخته‌اید، اجرای دوباره آن‌ها را تغییر نمی‌دهد. از اطلاعات قبلی یا دیتابیس تازه طبق بخش عیب‌یابی استفاده کنید.

آدرس `/` صفحهٔ استتار است، نه پنل؛ ممکن است به اینترنت وابسته باشد. مستقیم آدرس `/uipreview` را باز کنید.

## ۴. چه چیزهایی را بررسی کنم؟

این محیط دادهٔ نمایشی آماده ندارد؛ خالی بودن نمودارها و صفر بودن مصرف در شروع طبیعی است.

- ورود و خروج؛ نمایش فارسی، راست‌به‌چپ، رنگ‌ها و خوانایی متن.
- داشبورد و تب‌ها؛ تغییر اندازهٔ پنجره و حالت موبایل با ابزار توسعهٔ مرورگر.
- بخش اینباندها: بررسی یا ساخت یک اینباند آزمایشی برای انتخاب در فرم کاربر.
- ساخت کاربر آزمایشی: نام، حجم و انقضا؛ سپس ویرایش، جست‌وجو، فیلتر، غیرفعال‌سازی و حذف همان کاربر.
- باز شدن مودال‌ها، پیام موفقیت/خطا، لینک اشتراک و QR.
- ساخت پروفایل مسیریابی و نمایش آن در فهرست انتخاب پروفایل کاربر.
- تغییر یک تنظیم ظاهری، ذخیره و بارگذاری مجدد صفحه برای بررسی ماندگاری.
- دریافت بکاپ با داده‌های صرفاً آزمایشی؛ فایل بکاپ ممکن است حاوی اسرار باشد و نباید منتشر شود.

برای گزارش ایراد، نام تب، مراحل تکرار، تصویر و خطای Console/Network مرورگر را ثبت کنید؛ رمز، کوکی، API Key و توکن اشتراک را بپوشانید.

## ۵. توقف، اجرای مجدد و عیب‌یابی

**توقف:** در ترمینال سرور `Ctrl+C` بزنید. اجرای دوبارهٔ دستور بخش ۳ داده‌ها را حفظ می‌کند.

**پورت اشغال است:** اگر پیش‌نمایش قبلی هنوز اجراست، همان آدرس را امتحان کنید یا در دستور اجرا پورت را `8789` کنید و آدرس مرورگر را هم تغییر دهید.

**خطای `no such table` یا پاسخ ۵۰۰:** سرور را متوقف کنید، migration بخش ۲ را اجرا و دوباره سرور را راه بیندازید. مسیر ذخیره‌سازی دو دستور باید یکسان باشد. خطای دقیق در ترمینال Wrangler است.

**بعد از ورود دوباره صفحهٔ ورود می‌آید:** کوکی نشست `Secure` است. ابتدا از `localhost` استفاده کنید و بین آن و `127.0.0.1` جابه‌جا نشوید. اگر مرورگر کوکی را روی HTTP نپذیرفت، سرور را متوقف و با HTTPS اجرا کنید:

```powershell
npx wrangler dev --local --ip 127.0.0.1 --port 8788 --local-protocol https --persist-to .wrangler/ui-preview --var ADMIN_USER:admin --var ADMIN_PASS:ui-preview-2026 --var PANEL_PATH:uipreview
```

سپس **https://localhost:8788/uipreview** را باز کنید. Wrangler از گواهی توسعه استفاده می‌کند؛ ممکن است مرورگر هشدار بدهد. استثنای گواهی را فقط برای همین آدرس محلی تأیید کنید، نه سایت‌های دیگر. ویژگی `Secure` کوکی را از کد حذف نکنید.

**مسیر یا رمز قبلی را ندارید:** بدون حذف داده‌ها، در هر دو دستور migration و اجرا، `.wrangler/ui-preview` را به `.wrangler/ui-preview-fresh` تغییر دهید. دیتابیس خالی تازه ساخته می‌شود. پس از ساخت اولیه، تغییر `ADMIN_PASS` به‌تنهایی رمز موجود را عوض نمی‌کند.

## ۶. محدودهٔ تست و مرحلهٔ بعد

اجرای محلی برای بررسی UI و عملیات دیتابیس مناسب است؛ تأیید اتصال VPN روی شبکهٔ Cloudflare نیست. ثبت WARP، ساب بیرونی و سایر درخواست‌های خارجی همچنان اینترنت می‌خواهند. وب‌هوک تلگرام نمی‌تواند به localhost شما وصل شود. آمار واقعی Cloudflare، چندنودی و اجرای زمان‌بندی‌شدهٔ production نیز با این مرور UI تأیید نمی‌شوند. برای این بررسی توکن واقعی وارد نکنید.

بررسی‌های خودکار اختیاری:

```powershell
npm test
npm run check
```

`check` شامل typecheck و بیلد **dry-run** است، نه دیپلوی واقعی. تا وقتی آماده نشده‌اید، `npm run deploy`، `npm run db:create` یا `npm run db:remote` را اجرا نکنید. داده‌های آزمایشی محلی خودکار به D1 واقعی منتقل نمی‌شوند.

### وضعیت اعتبارسنجی این راهنما

migration محلی و بالا آمدن سرور روی پورت 8788 در این محیط بررسی شد. نتیجهٔ تست خودکار ورود قابل تأیید نبود؛ بررسی بصری در مرورگر و ورود تعاملی هنوز باید انجام شود. دستور HTTPS راه‌حل کوکی Secure است و در این بررسی اجرا نشده است.
